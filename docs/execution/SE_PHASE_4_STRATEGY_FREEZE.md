# SE Phase 4 Strategy Freeze

## STATE_BEFORE

Phase 4A optimized for a Founding Research Room, Discord integration, customer acquisition, outbound discovery, and a Demand Signal Radar. The live Discord gate remained incomplete because the authenticated bot was not installed in a target guild.

## CHANGE

Phase 4 is frozen as `SUPERSEDED_BY_STRATEGY`. Customer-acquisition runtime entry points are disabled by default. Discord live-gate debugging, DSR customer discovery, automated contact, and payment activation stop here.

## REASON

StructEvidence now follows `ENVIRONMENT_BEFORE_PURPOSE`: first build a domain-neutral habitat for observing how reality changes, then validate later uses without allowing acquisition goals to shape the canonical model.

## STATE_AFTER

Phase 5 derives Structural Event projections from existing append-only canonical objects. Public scanning is not activated, payment remains inactive, and no user contact is authorized.

## PRESERVED_ASSETS

- Phase 4 commits and execution reports
- Discord integration and Windows execution-node work
- DPAPI credential architecture
- Demand Signal Radar implementation and tests
- Request, Challenge, and Outcome canonical objects

## DEPRECATED_PATHS

- Discord community acquisition
- Demand-signal customer qualification
- Draft outreach and contact queues
- Founding-room recruitment
- Payment activation

Historical code is preserved. The legacy `/api/requests` acquisition endpoint requires the explicit `PHASE4_CUSTOMER_ACQUISITION_ENABLED=true` compatibility flag and otherwise returns HTTP 410.

## NEXT_PHASE

Phase 5A — Reality Evolution Habitat Foundation. Human review is required before Phase 5B and before any large-scale public scanning.
